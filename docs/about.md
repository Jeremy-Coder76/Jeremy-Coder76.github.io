## Arolo Solutions

In 2026 I left Cisco to join [**Arolo Solutions**](https://www.arolo-solutions.com/) — a French company building network automation software *by network engineers, for network engineers*.

**Why I joined**

After six years of building automation for Service Provider customers, the same pattern kept repeating: every project rebuilt the same foundations from scratch. What attracted me to Arolo is the idea of taking that deep field expertise — backbone, automation, multi-vendor — and turning it into software that can be deployed at any operator or enterprise, instead of re-inventing it customer by customer.

**What we build: Prelude**

Prelude is a modular, multi-vendor network automation suite designed to adapt to very different contexts — operators, enterprises and integrators. Rather than one monolithic platform, it's a toolbox you pick from:

| Module | What it covers |
|--------|----------------|
| **Device Onboarding** | From ZTP provisioning to the full configuration lifecycle |
| **Multi-Vendor Connectivity** | Any device, any vendor, through a single unified interface |
| **Data Collection** | gNMI, SNMP, Syslog and NetFlow unified in one engine, normalized into a vendor-agnostic model |
| **Service Lifecycle** | Create, modify and decommission services from one place — define intent, let the platform translate it into device configuration |
| **Topology & Monitoring** | Network state and topology built from the collected data |

**My role**

I work across the product: designing and building automation modules, normalizing multi-vendor data models, and making sure what we ship matches what operations teams actually need on day one — because I spent the last decade on the other side of that interface.

## My Philosophy

**Start Before You're Ready**
My first automation project was built in one week with almost zero Python experience. The best time to start is now, not after you've mastered every concept.

**Each Experience Builds on the Last**
From VBA scripts automating Word documents to CI/CD pipelines deploying configurations across Service Provider networks — every skill compounds.

**Automation Is a Mindset, Not a Tool**
The specific technology matters less than asking: *"Can this be automated?"*

**Build the Tool, Not Just the Script**
The step from "I automated my task" to "I built something others can deploy" is the one that changes everything. That's the step I took with Arolo.
